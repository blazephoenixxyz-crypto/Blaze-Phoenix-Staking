# Monte Carlo campaign: random walks over the whole surface, pre-registered

The campaign is BLIND. Everything above the `<!-- RESULTS -->` marker was written and committed
before the first run (commit on the base `82ac0d0`), and is not edited after results are seen. A
tolerance that turns out to be wrong is a finding, recorded below as such, not loosened. Everything
below the marker is regenerated by `node test/montecarlo/report.mjs` from the TSV lines the test
prints (`forge test --match-contract MonteCarloWalk -vv`), so it can be rebuilt by anyone.

## Pre-registration

### Seeds (fixed before any data was seen)

Batch `k` uses `seed_k = uint256(keccak256(abi.encodePacked("82ac0d0", uint256(k))))`: the short
hash of the base commit, which nobody writing this campaign chose, plus the batch index. Sequence
`j` of batch `k` starts its generator at `keccak256(abi.encodePacked(seed_k, uint256(j)))`, and the
generator is `xorshift`-style `keccak256` chaining: draw `i` is `keccak256(abi.encodePacked(state))`.
A failing case is therefore fully identified by `(k, j, i)`, and `MC_BATCH=k MC_SEQ=j` replays it.

Batches run locally: `k = 0..3` (`MC_BATCHES=4`). The deep CI job runs `k = 0..15`. Volume knobs
(`MC_SEQS` sequences per batch, `MC_ACTIONS` actions per sequence) scale the run to the time
budget and are not tolerances; the defaults are 24 sequences x 160 actions.

### Sampling (random over the whole space, boundary mass added on purpose)

Every draw is a mixture: one draw in five from a BOUNDARY set, two in five log-uniform, two in five uniform.

| variable | boundary set | log-uniform | uniform |
|---|---|---|---|
| stakers per sequence | 1, 2, 100, 200 | 1..200 | 1..200 |
| deposit amount (wei) | 1, 2, 1e18-1, 1e18, MIN_EMISSION_WEIGHT-1, MIN_EMISSION_WEIGHT, MIN_EMISSION_WEIGHT+1, cap-1, cap, cap+1 | 1..30M BZPX | 1..30M BZPX |
| lock days | 90, 91, 2554, 2555, maxDaysNow-1, maxDaysNow, maxDaysNow+1, 0, 89 | 90..maxDaysNow | 90..maxDaysNow |
| time jump | 1 s; to each halving boundary -1/0/+1 s; to emissionEnd -1/0/+1 s; to a live unlock -1/0/+1 s | 1 s..400 d | 1 h..60 d |
| borrow / repay / withdraw amount | 0, 1, max-1, max, max+1 (max = the contract's own quote) | 1..max | 1..max |
| loss (fraction of the pot) | 1 wei, 5%, 60%, 100%-1 wei | 0.01%..60% | 0.5%..60% |

Loss, `tripBreaker`, `declareEmergency` and the emergency exits are drawn only after 40 settled actions of the sequence, the same gate the repository's `EmergencyExitsHandler` uses, so a book exists when the emergency opens. Donations stop once the emergency is open (MC-EMG reads the backing at that moment). Whale-versus-dust: with probability 10% a sequence gives one staker a position near the wallet cap
and every other staker dust (1..1e18 wei). The action at each step is drawn uniformly from:
deposit, borrow, repay, withdraw, claimRewards, claimPureYield, lock (the reward-debt rebase),
pokeExpiredLock, pokeExpiredLocks, liquidate, donate, loss, tripBreaker, declareEmergency,
syncEquity, emergencyWithdraw, touchAuditSnapshot, passTime. The grid of named hypotheses in
`test/montecarlo/Hypotheses.t.sol` is an extra layer on top, never a substitute.

### Invariants, tolerances and failure criteria (fixed before the first run)

`DUST = 1e10` wei is `CONSERVATION_DUST` in the contract. Every invariant is asserted after EVERY
action of every sequence. One false assertion anywhere makes the test red and is reported with its
`(k, j, i)`; nothing is filtered.

| name | statement | tolerance |
|---|---|---|
| MC-CONSERVE | `backing + totalBadDebt + lossInjected` equals `netPrincipal + rewardReserve + protocolReserve + (distributed - paid) + donated`, the identity in the contract header; `lossInjected` is the ghost of tokens the walk removed from the contract (a loss event), which the identity cannot see until the book records it | abs diff <= DUST |
| MC-SOLVENT | `backing + totalBadDebt + lossInjected + DUST >= owed()`; with `lossInjected == 0` this is I9 as the contract states it | DUST |
| MC-EMIT-CAL | `totalRewardDistributed <= emittedAt(now)` (the schedule's closed form) and `rewardReserve + totalRewardDistributed == totalEmissionFunded` (no sweep in the walk) and `rewardReserve <= TOTAL_REWARDS` | 0 |
| MC-SHARE | `totalRewardsPaid + sum_i pendingRewards(i) <= totalRewardDistributed + DUST` (the sum over every staker is read every 8th action and at the end of the sequence, for the time budget), and after every action `pendingRewards(actor) <= totalRewardDistributed - totalRewardsPaid + DUST` for the actor it touched | DUST |
| MC-AUDIT | `auditInvariants() & 0b11100 == 0` always; bit 0 is 0 whenever `lossInjected == 0`; bit 1 is recorded, not asserted (the contract documents it as a soft signal) | 0 |
| MC-MONO | `accRewardPerShare` and `accPureYieldPerShare` never decrease | 0 |
| MC-DEBT | for every staker, `debt <= staked + DUST` (INV-19) | DUST |
| MC-EMG | after the emergency opens, every exit pays at most `staked + pendingRewards + pendingPureYield` of the position read just before it, and the sum of exits never exceeds the backing at the moment the emergency opened | DUST per exit |
| MC-CLOSED | `D = scheduled - totalRewardDistributed >= 0`, where `scheduled` is the ghost sum, over every state-changing call, of `emittedAt(now) - emittedAt(lastRewardTime)` taken when `totalBoostedEffective > 0` (before damping and before the reserve cap). In the one-staker hypothesis with weight >= MIN_EMISSION_WEIGHT and a fully funded programme, `D == 0` exactly | 0 |

Reported distributions (min / median / p99 / max, with the `(k, j, i)` of the maximiser): the
MC-CONSERVE diff, the residue `R = totalRewardDistributed - totalRewardsPaid - sum_i
pendingRewards(i)`: what the book still counts as distributed with no position to claim it (the
forfeits of emergency exits; since fix1112 the hatch returns their stale-weight excess to
`rewardReserve`, so it no longer sits in `R`) plus rounding, which is pro-protocol
(`R >= -DUST` is asserted); the maximiser is decomposed wei for wei in
`test/montecarlo/ResidueDecomposition.t.sol`, and `D`.

### Amendments recorded after the first run (batch 0, tree `94e1bdb` + the test): pre-registration errors, not contract findings

- **A1 (MC-SHARE).** As pre-registered it compared `pendingRewards` (a quote that projects the window not yet settled) with `totalRewardDistributed` and `totalRewardsPaid` (counters that move only when a transaction settles the window). After any time jump the quote exceeds the counters by the open window, by construction, and sequence `(0, 2)` and `(0, 20)` showed it at `i = 8` and `i = 24`. Restated: the sum and the per-actor read are taken only at settled instants (`lastRewardTime == lastInterestTime == block.timestamp`). The tolerance is unchanged.
- **A2 (MC-EMIT-CAL, MC-CLOSED).** As pre-registered they read `totalRewardDistributed` as the emission released. That counter also carries the interest flow that `_updateInterestIndex` credits to the pure-yield accumulator (`src/BlazePhoenixStaking.sol:1800`) and the LOCK-STALE corrections, so `totalRewardDistributed <= emittedAt(now)` and `rewardReserve + totalRewardDistributed == totalEmissionFunded` are false by construction once any interest accrues (first seen at `(0, 20, 27)`). Restated on the quantity the schedule governs: `released = totalEmissionFunded - rewardReserve`, with `released == sum of the windows as _windowReward prices them` (exact, 0 tolerance), `released <= emittedAt(now)`, and `D = scheduled - released`.
- **A2b (MC-EMIT-CAL).** The equality `released == mirrored windows` was wrong by one more term: a settle after a lock has lapsed inside the window returns the stale-weight excess to `rewardReserve` (`src/BlazePhoenixStaking.sol:1638`, LOCK-STALE), so `released` is at most the mirrored sum. Asserted as `released <= mirrored windows`, first seen at `(0, 1, 80)`.
- **A3 (MC-CONSERVE in a breached emergency).** The identity in the contract header describes the book outside the pro-rata haircut. Once a loss has been injected and the breaker has opened the emergency, an exit pays `principal * pot / eCorr` (H-05) and debits the whole principal, and the walk cannot rebuild the scaled term from the outside: first seen at `(0, 11, 157)` (47,748,210,847,041,621 wei, dust positions, 10,149,071 BZPX removed from the pot) and, with a ghost that tried to add `principal - paid` back, at `(1, 9, 133)` (7,927 BZPX, where that difference was the interest the exit had just debited, not a haircut). Restated: MC-CONSERVE is asserted on every action outside a breached emergency; inside one, the exits are governed by MC-EMG and MC-SOLVENT, and the identity's drift is still recorded in the samples and in the maximiser below. Tolerance unchanged. The in-suite default of the test is batch 0, sequences 0..2, so it fits the default gas limit; the campaign volume is run with `MC_BATCHES`, `MC_SEQS` and `--gas-limit`.
- **Added (MC-PAID).** `totalRewardsPaid <= totalRewardDistributed + DUST`, which is INV-16 as `test/InvariantsFullSurface.t.sol` states it, now asserted after every action.

### Re-run on the 8-year schedule (introduced in `385b297`)

The emission schedule changed after the first campaign: 8 years, a linear base of 60M plus a bonus
of 16M, 8M, 4M and 2M over four 2-year periods (biennial halving of the bonus). The campaign was
run again from the same pre-registration: the seeds (derived from `82ac0d0`), the sampling, the
invariants and the tolerances are unchanged. One line of the walk follows the schedule: the
"halving boundary" of the time-jump boundary set is the next of the three turns still ahead
(`start + k * period`, `k = 1..3`), where the first campaign had one. The results below replace
the first campaign's; the same seeds draw different walks on the new clock, so the maximisers are
new cases.
