## Pre-registration

### Seeds (fixed before any data was seen)

Batch `k` uses `seed_k = uint256(keccak256(abi.encodePacked("82ac0d0", uint256(k))))`: the short
hash of the base commit, which nobody writing this campaign chose, plus the batch index. Sequence
`j` of batch `k` starts its generator at `keccak256(abi.encodePacked(seed_k, uint256(j)))`, and the
generator is `xorshift`-style `keccak256` chaining: draw `i` is `keccak256(abi.encodePacked(state))`.
A failing case is therefore fully identified by `(k, j, i)`, and `MC_BATCH=k MC_SEQ=j` replays it.

Batches run locally: `k = 0..3` (`MC_BATCHES=4`). The deep CI job runs `k = 0..15`. Volume knobs
(`MC_SEQS` sequences per batch, `MC_ACTIONS` actions per sequence) scale the run to the time
budget and are not tolerances; the defaults are 24 sequences x 160 actions.

### Sampling (random over the whole space, boundary mass added on purpose)

Every draw is a mixture: 20% from a BOUNDARY set, 40% log-uniform, 40% uniform.

| variable | boundary set | log-uniform | uniform |
|---|---|---|---|
| stakers per sequence | 1, 2, 100, 200 | 1..200 | 1..200 |
| deposit amount (wei) | 1, 2, 1e18-1, 1e18, MIN_EMISSION_WEIGHT-1, MIN_EMISSION_WEIGHT, MIN_EMISSION_WEIGHT+1, cap-1, cap, cap+1 | 1..30M BZPX | 1..30M BZPX |
| lock days | 90, 91, 2554, 2555, maxDaysNow-1, maxDaysNow, maxDaysNow+1, 0, 89 | 90..maxDaysNow | 90..maxDaysNow |
| time jump | 1 s; to each halving boundary -1/0/+1 s; to emissionEnd -1/0/+1 s; to a live unlock -1/0/+1 s | 1 s..400 d | 1 h..60 d |
| borrow / repay / withdraw amount | 0, 1, max-1, max, max+1 (max = the contract's own quote) | 1..max | 1..max |
| loss (fraction of the pot) | 1 wei, 5%, 60%, 100%-1 wei | 0.01%..60% | 0.5%..60% |

Loss, `tripBreaker`, `declareEmergency` and the emergency exits are drawn only after 40 settled actions of the sequence, the same gate the repository's `EmergencyExitsHandler` uses, so a book exists when the emergency opens. Donations stop once the emergency is open (MC-EMG reads the backing at that moment). Whale-versus-dust: with probability 10% a sequence gives one staker a position near the wallet cap
and every other staker dust (1..1e18 wei). The action at each step is drawn uniformly from:
deposit, borrow, repay, withdraw, claimRewards, claimPureYield, lock (the reward-debt rebase),
pokeExpiredLock, pokeExpiredLocks, liquidate, donate, loss, tripBreaker, declareEmergency,
syncEquity, emergencyWithdraw, touchAuditSnapshot, passTime. The grid of named hypotheses in
`test/montecarlo/Hypotheses.t.sol` is an extra layer on top, never a substitute.

### Invariants, tolerances and failure criteria (fixed before the first run)

`DUST = 1e10` wei is `CONSERVATION_DUST` in the contract. Every invariant is asserted after EVERY
action of every sequence. One false assertion anywhere makes the test red and is reported with its
`(k, j, i)`; nothing is filtered.

| name | statement | tolerance |
|---|---|---|
| MC-CONSERVE | `backing + totalBadDebt + lossInjected` equals `netPrincipal + rewardReserve + protocolReserve + (distributed - paid) + donated`, the identity in the contract header; `lossInjected` is the ghost of tokens the walk removed from the contract (a loss event), which the identity cannot see until the book records it | abs diff <= DUST |
| MC-SOLVENT | `backing + totalBadDebt + lossInjected + DUST >= owed()`; with `lossInjected == 0` this is I9 as the contract states it | DUST |
| MC-EMIT-CAL | `totalRewardDistributed <= emittedAt(now)` (the schedule's closed form) and `rewardReserve + totalRewardDistributed == totalEmissionFunded` (no sweep in the walk) and `rewardReserve <= TOTAL_REWARDS` | 0 |
| MC-SHARE | `totalRewardsPaid + sum_i pendingRewards(i) <= totalRewardDistributed + DUST` (the sum over every staker is read every 8th action and at the end of the sequence, for the time budget), and after every action `pendingRewards(actor) <= totalRewardDistributed - totalRewardsPaid + DUST` for the actor it touched | DUST |
| MC-AUDIT | `auditInvariants() & 0b11100 == 0` always; bit 0 is 0 whenever `lossInjected == 0`; bit 1 is recorded, not asserted (the contract documents it as a soft signal) | 0 |
| MC-MONO | `accRewardPerShare` and `accPureYieldPerShare` never decrease | 0 |
| MC-DEBT | for every staker, `debt <= staked + DUST` (INV-19) | DUST |
| MC-EMG | after the emergency opens, every exit pays at most `staked + pendingRewards + pendingPureYield` of the position read just before it, and the sum of exits never exceeds the backing at the moment the emergency opened | DUST per exit |
| MC-CLOSED | `D = scheduled - totalRewardDistributed >= 0`, where `scheduled` is the ghost sum, over every state-changing call, of `emittedAt(now) - emittedAt(lastRewardTime)` taken when `totalBoostedEffective > 0` (before damping and before the reserve cap). In the one-staker hypothesis with weight >= MIN_EMISSION_WEIGHT and a fully funded programme, `D == 0` exactly | 0 |

Reported distributions (min / median / p99 / max, with the `(k, j, i)` of the maximiser): the
MC-CONSERVE diff, the rounding residue `R = totalRewardDistributed - totalRewardsPaid - sum_i
pendingRewards(i)` (rounding is pro-protocol: `R >= -DUST` is asserted), and `D`.
